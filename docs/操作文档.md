## 4.2 上传数据的完整流程

平台按内容自动识别 4 条路线，用户无需先选：

| 路线 | 上传什么 | 处理方式 |
|---|---|---|
| ① 交付表 | 含 `items_task1.csv` 的 zip（可含公告表） | 直接入库，秒级 |
| ② 原始 HTML | 文件夹或平铺多选的 `<公告号>.html`，可带同名 `_file.zip` | 逐篇抽取；有 Key 走 LLM，失败回退规则层 |
| ③ 官方三表 | 含「总表/标的表/投标人表」sheet 的 xlsx，或含 `标的表.csv` 的 zip/CSV | 映射后入库，跳过「说明/示例」行 |
| ④ 单篇附件包 | 无 HTML 的 zip：pdf/docx/xls/图片，可套娃 | 只解析本次上传的附件 |

操作分三步：

- **第 1 步 选择/拖入**：拖入虚线区、点击选择文件，或点右上「选择文件夹」。多选多个 `.html` 会合并成一次导入，同批 `_file.zip` 按公告号配对。
- **第 2 步 覆盖确认**（仅当前库非空时）：标题「当前平台已有数据，请选择入库方式」，正文写出现有规模。三个出口：

| 点击 | 行为 |
|---|---|
| 覆盖并上传 | `replace`：清空后重建，只剩本次数据，提示「当前平台数据将被替换」 |
| 保留原数据并解析 | `append`：保留现有数据，按行去重后**追加**，提示「新数据将追加到现有数据之后」 |
| 右上 X / Esc | 真取消，不发请求，原数据不动，提示「已取消，未做任何改动」 |

注意：中间按钮仍会上传；只有 X/Esc 才放弃。

- **第 3 步 看进度并等待完成**：状态依次为「排队中/处理中/已完成/失败」，阶段文字说明当前动作；右侧总秒数与「单篇 XX ms」即处理速率口径（落盘完成 → 全部入库）。完成时提示「数据集处理完成」，规模与各页自动刷新，**无需手动刷新**。

失败时状态为「失败」，下方给可读原因；超限处理见 FAQ Q3。

## 6.2 为什么某些场景为空

平台不编造关系：查不到就返回空表/空图，指标显示 0 或错误提示。

- **S3 为空**：数据缺 `cobidding`（共同竞标）或 `bid`（投标参与）关系。典型是只上传「官方三表」——三表只有中标供应商、没有参与投标方；或只传单篇附件包、正文没有开标一览表。
- **S2 为空**：该采购方只有中标结果、没有投标人名单。
- **S1 为空**：该采购方无合作记录，或「最少次数」过滤过严；先把最少次数调到 1。
- **S4/S5 为空**：所选供应商没有共同采购方/共同项目；只选 1 个时提示「至少选 2 个供应商」。
- 想让 S2/S3/S5 有结果，需上传**含投标人名单**的数据（带开标一览表/评审结果表，或官方三表的投标人表），或点「恢复默认数据」。

# 7. 模型配置

## 7.1 Key 的唯一来源

页面 Key 是**全平台唯一来源**：进程强制 `EDM_KEY_SOURCE=ui`，只读「模型配置」页保存的 Key，**不读环境变量、不读 `.env`**。Key 只回显末 4 位掩码，不显示明文；保存在 `app/out/platform/llm_settings.json`。

（截图位置：模型配置表单与状态标签；正文示例：见图 8）

## 7.2 保存、测试、清除

- **填 Key**：左侧「模型配置」，填 API Key（`sk-` 开头；留空表示不修改）、Base URL、模型名；后两项留空则沿用当前值。
- **保存**：点「保存」→「已保存并即时生效」，无需重启；状态标签变「页面输入」。
- **测试连接**：用**已保存的生效配置**（不是未保存的输入）发最小调用。成功显示「连接成功 · 模型名 · 延迟 ms」；失败给可读原因（鉴权、权限、接口/模型不存在、限流、超时或无法连接）。
- **清除**：点「清除」→ 确认后提示「已清除：平台不再使用任何 Key，上传解析回退规则层」。

**LLM 何时参与**：路线②（原始 HTML）与路线④（单篇附件包）解析时使用文本模型；无 Key 或调用失败自动回退规则层，message 写「LLM N 篇 / 规则层回退 M 篇」。路线①（交付表）与路线③（官方三表）为结构化直接入库，**不调用模型**。

## 7.3 视觉模型的如实说明

「视觉模型（扫描件/图片 → 文本）」分组可填写并保存，但**当前平台上传解析管线未启用视觉通道**（初始化 `use_vlm=False`）。因此视觉 Key/Base URL/模型名会保存、会显示状态，但**不参与抽取**；扫描件 PDF、图片仍按规则层处理，抽不到文本不臆造。

# 8. API 使用（可选）

在线文档 `/api/docs`（Swagger，点 **Authorize** 填 token）；只读版 `/api/redoc`。除 `/health`、`/auth/login` 外均需 `Authorization: Bearer <token>`。

常用接口：`POST /api/v1/auth/login`（token 有效期 43200 秒）；`GET /api/v1/health`；`GET /api/v1/dataset/stats`；`GET /api/v1/items`（支持日期/金额/排序参数）；`GET /api/v1/scenarios/s1`~`/s5`（S4/S5 的 `suppliers` 重复传参）；`GET /api/v1/export/official`（加 `/{表名}` 下载单张 CSV）。

```bash
BASE=http://127.0.0.1:8000
TOKEN=$(curl -s -X POST "$BASE/api/v1/auth/login" \
  -H 'Content-Type: application/json' \
  -d '{"username":"reviewer","password":"ict2026"}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['token'])")

# 检索（关键词 + 分页）
curl -s -G "$BASE/api/v1/items" --data-urlencode "keyword=光" \
  -d page=1 -d page_size=20 -H "Authorization: Bearer $TOKEN"

# 场景 S1（中文参数需 URL 编码）
curl -s -G "$BASE/api/v1/scenarios/s1" \
  --data-urlencode "purchaser=东莞职业技术学院" -d top_n=5 \
  -H "Authorization: Bearer $TOKEN"

# 下载官方格式 xlsx
curl -s -o 官方数据集提取结果.xlsx "$BASE/api/v1/export/official" \
  -H "Authorization: Bearer $TOKEN"
```

Windows PowerShell 中 `curl` 是 `Invoke-WebRequest` 别名，建议用 `curl.exe` 或 `Invoke-RestMethod`。

# 9. 常见问题（FAQ）

**Q1：页面打不开/连接被拒绝。** 确认服务在跑：`ss -lntp | grep 8000`（Windows：`netstat -ano | findstr :8000`）。进程在跑但外网不通，检查云主机**安全组**与防火墙是否放行端口；端口被占用就换端口（`--port 8001`），地址与安全组同步改。

**Q2：页面样式错乱、`/assets/*.js` 404。** 多为解压不完整或缓存旧版本：先 **Ctrl+F5 强刷**；仍 404 就重新解压 `task3/backend/static/`，或 `npm run build` 重建。不要在 2C4G 机器上常驻 `vite dev`。

**Q3：上传被拒，提示超出上限。** 默认单次上传 **2048 MB**，解压上限（总量/单文件）**8192 MB**、条目 **20000**。3.4 GB 整包会超限：推荐 `platform/ingest.py` 脱机入库，或拆分上传；确需放宽时启动前设 `EDM_MAX_UPLOAD_MB=8192` 并留足磁盘。

**Q4：上传成功但场景为空（尤其 S2/S3）。** 先看数据有没有**投标关系**。只传「官方三表」或单篇附件包时，通常只有中标供应商、没有参与投标方，S2/S3 必然为空，S5 也可能为空；这不是查询失败。换含投标人名单的数据，或点「恢复默认数据」。

**Q5：上传小样本后库里的数据变少。** 选了「覆盖并上传」（`replace`）就会整库替换，属预期。要保留旧数据，下次选「保留原数据并解析」；已覆盖则点「恢复默认数据」回到完整交付集。

**Q6：启动日志提示 Neo4j 不可用，有影响吗？** 没有影响，平台自动回退 SQLite 图库，功能照常；查询耗时通常 13–28 ms（Neo4j 版 12–287 ms）。要用 Neo4j：确认 console 在跑、连接参数正确、7687 放行，再重启。

**Q7：中文显示乱码。** Linux 启动前 `export LANG=C.UTF-8`；Windows 先 `$env:PYTHONUTF8=1`。下载的 CSV 用 UTF-8 打开，Excel 建议「数据 → 从文本/CSV」并选 UTF-8。

**Q8：Windows 长路径导致解压报错。** 解压到短路径（如 `D:\ict\`），或运行 `app/scripts/repair_long_paths.py`；上传文件名建议短于 200 字符。

# 11. 数据与合规声明

## 11.1 数据来源

数据来自赛题五基准数据集（赛方发放），不含外部采购或编造数据。交付基线：公告 **1038** 篇、标的 **6244** 条，官方三表 **1768/6244/3259** 行。

## 11.2 模型与密钥

文本抽取使用 OpenAI 兼容接口的 `deepseek-flash`（DeepSeek 系列），参数规模官方未公开，如实标注「未公开」，见 `app/deliverables/model_manifest.json`。Key **只从页面读取**（`EDM_KEY_SOURCE=ui`），不读环境变量/`.env`；响应、页面与日志只出现掩码。启用 LLM 时文本会发送到所填 Base URL 的模型服务；不填 Key 则纯本地规则层。

## 11.3 调用日志

`app/out/llm_calls.jsonl` 只记元数据：时间、角色、模型 id、耗时、成功/失败、token 数、响应 id；**不含 API Key，也不含公告原文或 prompt**。

## 11.4 口径与自一致性

- **三表自洽**：三表共用 `(UUID, 标段/合同包)` 键；未分包写「未分包」，UUID 用公告号，不编造；金额统一万元。
- **页面统计 vs 图库节点**：卡片供应商 1378、品牌 1260 来自平台标的表；Neo4j 供应商 2604、品牌 1238 来自关系库实体口径（含参与投标方与别名归并），两者不等价；场景以图库为准，卡片以平台库为准。
- **准确性口径**：P/R/F1 是「与同族 LLM 标注的一致性」，不是独立人工盲标精度，引用时应写明口径，详见《提交说明与运行指南》与 `scripts/val_eval.py`。
