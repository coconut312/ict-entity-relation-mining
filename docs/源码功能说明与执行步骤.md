### 2.2 三分类：源码 / 产物 / 运行时生成

| 目录 | 性质 | 是否随包（`pack_delivery.py --with-raw-json`） | 说明 |
|---|---|---|---|
| `app/ict_parse/`、`app/platform/*.py`、`app/scripts/*.py` | **源码** | 是 | Python 源文件；`scripts/_*` 测试残留与 `__pycache__` 不进包 |
| `app/task3/backend/app/`、`integrations/`、`run.py`、`smoke_test.py` | **源码** | 是 | FastAPI 后端与上传管线 |
| `app/task3/frontend/src/` | **源码** | 是 | Vue 3 源码（改它才需要 npm 重建） |
| `app/task3/backend/static/` | 构建**产物** | 是 | 前端 `npm run build` 输出；部署直接托管，无需 Node |
| `app/deliverables/` | 交付**产物/数据** | 是 | 交付表、官方三表、Neo4j 导出、成品文档 |
| `app/data/`、`app/valset/` | 静态**数据** | 是 | 品目目录与人工核验真值 |
| `app/out/` | **运行时产物，不进包** | 仅白名单 | `out/full/**/items_llm.json`、`items.json`、`task2/graph.db`、`llm_calls.jsonl`、`data_quality_profile.json` 收录；`platform/platform.db`、附件副本、`_*` 测试目录一律排除 |
| `app/.venv/`、`node_modules/`、`__pycache__/` | 依赖/缓存 | 否 | 可重装/重建 |
| `提交材料/` | 提交暂存 | 否 | 打包器显式排除，避免「包中包」 |

> **一句话**：`out/` 是**可重建的运行时目录**（服务库、关系库、逐篇 JSON），源码与交付表才是权威输入。
> 注意 `提交材料\` 本身不进 zip；本文的 md/docx/pdf 放在**仓库根**，因此会以
> `ict_任务一二三_整合包/源码功能说明与执行步骤.*` 进入包内。

## 2 模块功能说明

### 3.1 `app/ict_parse/` —— 任务一解析与抽取核心

## 3 执行步骤（从零到可访问）

> 全部命令在 `app/` 下执行。PowerShell 建议先 `$env:PYTHONIOENCODING="utf-8"`；bash 可 `export PYTHONIOENCODING=utf-8`。
> 每步给出「命令 + 实测预期输出」；输出中的路径/端口随环境变化。

### 步骤 1：准备环境（Python 3.14 + uv）

```powershell
uv --version
uv python install 3.14
```

预期（实测）：`uv 0.11.9 (7829a03b6 2026-05-05 x86_64-pc-windows-msvc)`。
`uv` 会按 `app/.python-version`（内容 `3.14`）与 `pyproject.toml` 的 `requires-python >= 3.14` 选取解释器；
本仓库实测虚拟环境为 **Python 3.14.4**（`app/.venv`）。低于 3.14 无法 `uv sync`。

### 步骤 2：安装依赖（两条路径，差异必须知道）

```powershell
cd app
uv sync
```

- **推荐**：`uv sync` 按 `uv.lock` 安装 `pyproject.toml` 的**全量**依赖
  （beautifulsoup4 / lxml / pdfplumber / python-docx / openpyxl / openai / fastapi / uvicorn / neo4j / rapidocr 等）；
  解析 HTML、解析附件、生成 docx 都靠它。
- **最小集**（只有 pip 环境时）：

```powershell
python -m venv .venv
.venv\Scripts\pip install -r task3\backend\requirements.txt
```

`requirements.txt` 只含 **fastapi / uvicorn / pydantic / python-multipart / openai / openpyxl**，
`neo4j` 被注释掉。它够「起平台 + 交付表入库 + 检索/场景/下载」；**不够**上传原始 HTML / 附件包
（那两条路线要 bs4/lxml/pdfplumber/python-docx）。因此演示上传功能请用 `uv sync`。

### 步骤 3：建服务库 `out/platform/platform.db`（必做，约 0.25 秒）


### 6.1 需要 LLM Key 的环节（只有两类）

| 场景 | 入口 | Key 来源 |
|---|---|---|
| **平台上传**原始 HTML（路线②）/ 附件包（路线④） | `integrations/pipeline_impl.py` → `llm_extract.extract_with_llm_safe()` | **只有一个来源：页面「模型配置」**。`run.py` 设 `EDM_KEY_SOURCE=ui`，平台不读 `.env`、不读环境变量，保存后立即生效、无需重启 |

- 调用日志：`app/out/llm_calls.jsonl`（仅元数据，不含 Key/prompt）。本文实测该文件 **2,420 行**，可作「无新增调用」的对照基线。

### 6.3 Neo4j 是可选项（不可用时平台自动回退）

`run.py` 的判定顺序（源码 `run.py:87-111`）：

1. `EDM_GRAPH_REPOSITORY` 含 `neo4j_repo` → 用 3 秒超时探测 bolt + `RETURN 1`；
2. 探测失败 → 打印 `[警告] Neo4j 不可用（原因）→ 已回退 SQLite 图库` + 本机 Neo4j 启动/建图/验证指引，
   并把 `EDM_GRAPH_REPOSITORY` 改写为 `integrations.repos:SQLiteGraphRepository`；
3. 记录 `EDM_GRAPH_BACKEND_ACTIVE`（`neo4j` / `sqlite`）；若 `EDM_SQLITE_PATH` 不是默认平台库（副本库/测试库），
   强制 `EDM_GRAPH_SYNC=0`，避免把共享图重置成本次上传的小数据集。

因此：**不装 Neo4j，页面与 S1–S5 全部照常可用**，只是场景数据来自 SQLite 视图而非 Cypher。

## 6 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|

| 场景分析 P95 变慢 | 走的是 CSV 回退而非 `graph.db` | 看 `_meta.derived_source` 是否为 `graph.db`；确认 `out/task2/graph.db` 存在 |

## 7 附：关键文件清单与注释覆盖

### 8.1 统计口径（可复算）

- **总行数** = 文件物理行数（含空行与 docstring）。
- **Python 注释行** = 以 `#` 开头的行 + 模块/类/函数 docstring 所占行（`ast` 定位，含首尾引号行）。
- **JS/Vue 注释行** = 去掉缩进后以 `//`、`/*`、`*`、`<!--` 开头的行。
- **注释率** = 注释行 ÷ 总行数，保留 1 位小数。下表为 2026-10-17 实测。
