# 部署说明（云端 2C/4G 从零到可用）

> 适用对象：评审方 / 运维同学 / 未来接手的人。
> 目标：在一台**全新的 2 核 4G 云主机**上，只用本压缩包里的东西，把「任务一/二数据 + 任务三平台」跑起来。
> 本包内已包含：全部交付数据表、任务二关系库 `graph.db`、Neo4j 导出件、平台代码与**已构建好的前端静态资源**。
> 本包内**不含**：原始赛题数据集（约 3.4 GB，赛方发放）、`.venv`/`node_modules` 依赖目录、`.git` 历史、演示 PPT/视频、`out/platform/platform.db`（服务库，需本地生成，见步骤 3）。

---

## 0. 五分钟速部署（TL;DR）

```bash
# 0) 解压后进入 app/
cd ict_任务一二三_整合包/app

# 1) 装 Python 3.14 + uv
curl -LsSf https://astral.sh/uv/install.sh | sh
uv python install 3.14

# 2) 装依赖（uv.lock 已锁定版本，可复现）
uv sync

# 3) 生成服务库（只读 deliverables/ + out/task2/graph.db，不碰原始数据集）
uv run python platform/ingest.py --db out/platform/platform.db

# 4) 起服务（0.0.0.0:8000，单进程同时提供接口与页面；端口可自选）
uv run python task3/backend/run.py --host 0.0.0.0 --port 8000
```

浏览器打开 `http://<主机IP>:8000/`，账号 **reviewer / ict2026**。
可选的 Neo4j 图库见步骤 4；不装 Neo4j 也能完整使用（自动回退 SQLite 图库）。
> 端口可自选（示例用 8000）；若云主机安全组只放行其它端口（如 8080），启动时用 `--port 8080` 并在安全组放行同一端口。

## 2. 安装 Python 与依赖

```bash
# Linux / macOS
curl -LsSf https://astral.sh/uv/install.sh | sh
# Windows PowerShell
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"

cd ict_任务一二三_整合包/app
uv python install 3.14          # 首次执行会下载 CPython 3.14
uv sync                         # 建 .venv/ 并按 uv.lock 装全部依赖
```

- `uv sync` 装的是 `pyproject.toml` 里的依赖（fastapi / uvicorn / neo4j / openpyxl / pdfplumber / python-docx / rapidocr 等），**不含 torch/transformers**（2C4G 友好的刻意选择）。
- 只有 pip 环境时可用：`python -m venv .venv && .venv/bin/pip install -r task3/backend/requirements.txt`（仅够跑平台，不含抽取管线的重型依赖）。
- 国内网络慢可先设镜像：`export UV_DEFAULT_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple`。

## 3. 生成服务库 `out/platform/platform.db`（必做）

平台读的是 SQLite 服务库，**本包不提供它**（属可再生产物），必须用包内数据生成一次：

```bash
cd ict_任务一二三_整合包/app        # 实际目录名以解压为准
uv run python platform/ingest.py --db out/platform/platform.db
```

输入与输出（全部在包内，不需要原始数据集、不需要调模型）：

| 输入 | 用途 |
|---|---|
| `app/deliverables/items_task1.csv`（6244 行） | 标的物明细 → `t1_item` |
| `app/deliverables/announcements_task1.csv`（1038 行） | 公告级 → `t1_notice` |
| `app/out/task2/graph.db`（3.2 MB） | 任务二实体/投标/公告 + 10 张关系画像视图（**部署必需，已随包**） |
| `app/deliverables/task2_*.csv`（14 张） | `graph.db` 缺失时的回退来源 |

期望输出（JSON 摘要）：

```json
{
  "counts": {"t1_item": 6244, "t1_notice": 1038, "entity": 3401, "bid": 3240, "...": "..."},
  "derived": {"source": "graph.db", "empty_after": []},
  "noise": {"enabled": true, "dropped": 0}
}
```

校验：

```bash
uv run python -c "import sqlite3;c=sqlite3.connect('out/platform/platform.db');print(dict(c.execute('select k,v from _meta')))"
# 关键三项：pages=1038  total_rows≈37043  derived_source=graph.db
```

> 若 `derived_source` 显示 `deliverables-csv`，说明 `graph.db` 没找到（路径错/未解压全），平台仍可用，但 S1「产品供应商」口径会与 Neo4j 版略有差异（见 `docs/task2-neo4j.md`）。
> 入库耗时实测 < 1 秒（1038 篇），可直接重跑，幂等。

## 4.（可选）Neo4j 图库

赛题推荐 Neo4j。规模很小（节点 5,645 / 关系 14,143），2C4G 完全够用。

```bash
# 4.1 安装（Ubuntu 示例，也可用官方 tarball 解压即用）
sudo apt install -y openjdk-17-jre-headless
wget https://dist.neo4j.org/neo4j-community-5.25.1-unix.tar.gz && tar xzf neo4j-community-5.25.1-unix.tar.gz
# 4.2 设初始口令（与平台默认一致）
neo4j-community-5.25.1/bin/neo4j-admin dbms set-initial-password ict2026neo4j
# 4.3 启动
neo4j-community-5.25.1/bin/neo4j console
```

**内存配置（4 GB 机器强烈建议改，否则 Neo4j 默认会抢走大半内存）**——编辑 `conf/neo4j.conf`：

```properties
dbms.memory.heap.initial_size=1G
dbms.memory.heap.max_size=1G
dbms.memory.pagecache.size=512M
# 只本机访问可保持默认；需远程 Browser 访问改成 0.0.0.0
server.default_listen_address=0.0.0.0
server.bolt.listen_address=:7687
server.http.listen_address=:7474
```

建图（幂等，可重复执行）：

```bash
cd app
export NEO4J_URI=bolt://127.0.0.1:7687 NEO4J_USER=neo4j NEO4J_PASSWORD=ict2026neo4j
uv run python scripts/build_neo4j_graph.py --load --wipe        # 只装载，不改交付件
uv run python scripts/verify_neo4j.py                           # 期望：可比项 11、一致 11
```

> `--export` 会**重写** `app/deliverables/neo4j/*.csv` 与 `task2_graph.cypher`（内容幂等）。只想验证装载就**不要**加 `--export`。
> 不想装 Neo4j：跳过本节。`run.py` 探测不到 bolt 会打印指引并自动回退 SQLite 图库，页面与五大场景照常可用。

## 5. 启动服务

```bash
cd app
uv run python task3/backend/run.py --host 0.0.0.0 --port 8000
```

- 启动日志会打印：接口地址、服务库是否存在、图库后端（neo4j / SQLite 回退）、登录账号。
- 单进程同时托管 API 与前端静态资源（`task3/backend/static/`），**不需要再起 Nginx 或 `vite dev`**。
- 常驻运行（Linux，**推荐 systemd**）：把下列内容保存为 `/etc/systemd/system/ict-platform.service`（路径按实际解压位置调整，示例为 `/opt/ict`）：

```ini
[Unit]
Description=ICT Platform (Task 1/2/3 FastAPI + static UI)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/ict/app
ExecStart=/opt/ict/app/.venv/bin/python task3/backend/run.py --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ict-platform
sudo systemctl status ict-platform          # 查看状态
sudo journalctl -u ict-platform -f          # 跟踪日志
```

> 临时调试才用 `nohup`（不随开机自启、进程挂了不会自动拉起）：
> `nohup /opt/ict/app/.venv/bin/python task3/backend/run.py --host 0.0.0.0 --port 8000 > app.log 2>&1 &`
> 注意 `run.py` 需用 `.venv` 里的解释器启动（上面 `ExecStart` 已写绝对路径）。

- 云主机安全组放行 **8000**（平台）、**7474/7687**（仅当需要远程访问 Neo4j 时）。

> 端口可自选（示例用 8000）；若云主机安全组只放行其它端口（如 8080），启动时用 `--port 8080` 并在安全组放行同一端口（systemd 的 `ExecStart` 同步改成 `--port 8080`）。

## 9. 常见问题（FAQ）

**Q1：页面能开但所有列表为空 / 数据总览显示"暂无数据"。**
`out/platform/platform.db` 没生成或里面是测试数据。按步骤 3 重跑 `platform/ingest.py`，再刷新。

**Q2：启动日志出现「[警告] Neo4j 不可用 → 已回退 SQLite 图库」。**
正常现象，平台照常可用。要接 Neo4j：确认 `neo4j console` 在跑、`NEO4J_URI/NEO4J_PASSWORD` 对、防火墙放行 7687，然后重启服务。

**Q3：上传基准数据集（约 3.4 GB zip）失败 / 报超出大小限制。**
默认 `EDM_MAX_UPLOAD_MB=2048`（2 GB），3.4 GB 的整包会被拒。两种解法：
- 脱机入库（推荐，快且稳）：直接用 `platform/ingest.py` 生成服务库，不必上传；
- 放宽限制：启动前 `export EDM_MAX_UPLOAD_MB=8192`（同时注意磁盘空间，解压上限是它的 4 倍）。

**Q4：前端页面 404 或 `/assets/xxx.js` 404。**
`task3/backend/static/` 不完整（解压时被杀毒/网盘截断）。从包里重新解压该目录；或 `cd task3/frontend && npm ci && npm run build`（产物直出 `backend/static/`）。**不要**在评测机上常驻 `vite dev`（内存 1 GB+）。

**Q5：场景查询超过 1 秒。**
先确认步骤 3 用的是 `graph.db`（`derived_source=graph.db`），别走 CSV 回退；确认机器没被其它进程占满；`platform.db` 与 `graph.db` 放本地盘（别放网络盘）。

**Q6：Windows 上解压后路径过长报错。**
包内有 `app/scripts/repair_long_paths.py`；或解压到短路径（如 `D:\ict\`）。

**Q7：中文输出乱码。**
Linux 设 `export LANG=C.UTF-8`；Windows PowerShell 先 `$env:PYTHONUTF8=1`。

**Q8：端口被占用。**
`ss -lntp | grep 8000`（Windows：`netstat -ano | findstr :8000`）找到进程后换端口：`--port 8001`。

**Q9：改了口令/端口后怎么重启。**
先 `kill` 旧进程再启动（`uv run` 启动的进程不能热改环境变量）；改了 Vue 源码才需要重启+重新 build。
