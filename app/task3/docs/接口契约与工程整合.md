## 二、接口契约

所有接口前缀 `/api/v1`，全部返回 JSON。
**完整定义见 `backend/app/schemas.py`，在线可交互文档见 `/api/docs`。**

### 系统（公开）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查 + 数据状态（`has_data` 决定前端是否显示空态引导） |
| POST | `/auth/login` | 登录，返回 Bearer 令牌（12 小时有效） |
| POST | `/auth/logout` | 登出，使令牌立即失效 |
| GET | `/auth/me` | 当前登录用户 |

### 鉴权约定

赛题要求「提供评审方登录系统的操作说明及账号」，因此**除上表 4 个接口外，
其余接口全部需要 `Authorization: Bearer <token>`**，未登录返回 `401`。

实现要点（见 `backend/app/auth.py`）：

* token 存**进程内存**，不引入 Redis / 数据库 / JWT 库 —— 评测机 2 核 4G，省一个常驻进程就是收益
* 校验是 dict 查表 + 一次时间比较，**O(1)，对「查询效率 <1 秒」这个 10 分项无影响**
* 口令用 PBKDF2-SHA256（20 万次迭代）派生后保存，比较走 `secrets.compare_digest`（常量时间）
* 账号通过 `EDM_AUTH_USERS` 环境变量配置，格式 `用户名:口令,用户名:口令`
* 默认账号：`reviewer / ict2026`、`admin / admin2026`（**部署前务必改掉**）

### 数据集

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/dataset/stats` | 概览：公告数、标的数、实体数、字段填充率 |
| POST | `/dataset/import` | 上传数据集（multipart），返回 `job_id` |
| GET | `/dataset/import/{job_id}` | 轮询处理进度与耗时 |

### 任务一 · 标的物检索

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/items` | 条件检索（分页） |
| GET | `/items/facets` | 筛选器取值域 |

### 任务二 · 五大场景

| 方法 | 路径 | 参数 |
|---|---|---|
| GET | `/scenarios` | — |
| GET | `/scenarios/s1` | `purchaser`, `min_count`, `top_n` |
| GET | `/scenarios/s2` | `purchaser`, `top_n` |
| GET | `/scenarios/s3` | `supplier`, `top_n` |
| GET | `/scenarios/s4` | `suppliers`（重复参数）, `min_count`, `top_n` |
| GET | `/scenarios/s5` | `suppliers`（重复参数）, `top_n` |

> ⚠️ 场景 4/5 的 `suppliers` 是**重复查询参数**（`?suppliers=A&suppliers=B`），
> 不是数组语法。前端 `src/api/index.js` 里的 `repeatParams()` 已处理。

### 实体

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/entities/suggest?q=&type=` | 实体自动补全（远程搜索，不全量拉取） |

### 接口裁剪记录

按赛题评分权重做过一次裁剪 —— 决赛里**平台功能完整性只值 5 分，而「查询效率 <1 秒」值 10 分**，
因此不在赛题要求内、且界面用不到的能力一律移除，减少维护面与渲染负担：

| 已删除 | 理由 |
|---|---|
| `GET /items/export` | 赛题未要求导出功能 |
| `GET /items/{id}` | 详情改为表格行内展开，少一层浮层，也少一次请求 |
| `GET /dataset/jobs` | 导入历史非赛题要求；处理进度已由 `/dataset/import/{job_id}` 覆盖 |
| `GET /entities/{id}/profile` | 未接入任何页面 |

**当前接口共 16 个**（4 个公开 + 12 个需登录，其中含 5 个场景接口）。

## 四、合并步骤（照做即可）

```bash
# ── 1. 取代码 ──────────────────────────────────────────────
git clone <repo> && cd <repo>

# ── 2. 后端环境 ────────────────────────────────────────────
cd backend
python -m venv .venv
.venv\Scripts\activate            # Linux: source .venv/bin/activate
pip install -r requirements.txt
python smoke_test.py              # 期望：通过 26 项，失败 0 项

# ── 3. 启动后端（开发模式，带热重载）──────────────────────
uvicorn app.main:app --reload --port 8000

# ── 4. 前端环境（另开一个终端）────────────────────────────
cd frontend
npm install
npm run dev                       # 打开 http://localhost:5173

# ── 5. 生产构建（前端产物直出 backend/static）─────────────
npm run build
# 之后只需启动后端一个进程，访问 http://<host>:8000 即可
```

**合并时的冲突高发区，已提前规避：**

| 潜在冲突 | 规避方式 |
|---|---|
| 各自 `requirements.txt` 不一致 | 后端只有一份，任务一/二的依赖追加到同一文件 |
| 各自的配置散落 | 全部集中在 `backend/app/config.py` |
| 前端硬编码接口地址 | 统一走 `/api/v1`，开发期由 Vite 代理，生产期同源 |
| 各自定义数据模型 | 契约只在 `schemas.py` 一处定义 |
| 数据库连接串写死 | 通过环境变量注入 |
| 端口冲突 | 后端 8000 / 前端 5173，固定 |

## 五、部署到评测云主机（2 核 4G Ubuntu）

```bash
# 1) 先加 swap —— 4G 内存没有 swap 会 OOM
sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 2) 依赖
sudo apt update && sudo apt install -y python3.11 python3.11-venv nginx

# 3) 后端（只开 1 个 worker —— 内存有限）
cd backend
python3.11 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1

# 4) 前端产物已经由 FastAPI 托管，无需额外配置 Nginx
```

**内存纪律（务必遵守）：**

1. 前端必须 `npm run build` 成静态文件，**评测机上绝不能跑 `vite dev`**（dev server 要 1 GB+）
2. 后端不引入 `torch` / `transformers` / `paddleocr`
3. 处理过程流式进行，不要把全量中间结果驻留内存
4. 不部署 Redis，缓存用进程内 LRU + 数据库索引

## 六、与赛题评分点的对应

**评分权重（决定了本平台的取舍）：**

| 评分项 | 校内赛 /25 | **决赛 /20** |
|---|---|---|
| 平台功能完整性（任务一处理+检索 各半） | 15 | **5** |
| 技术栈合规性 Vue + Python | 5 | 5 |
| **查询效率（单次 < 1 秒）** | 5 | **10** |

> 决赛里「查询效率」是任务三最大的单项（10 分），而「功能完整性」只有 5 分。
> 因此设计上刻意**不做赛题未要求的功能**，把成本全部投在"快"和"清楚"上。

| 赛题要求 | 本平台对应实现 |
|---|---|
| 数据集自动化处理 | 「数据总览」页顶部上传区 → `POST /dataset/import` → `Pipeline` |
| 标的物全字段检索、筛选与查看 | 「标的物检索」页 → `GET /items`、`GET /items/facets`（详情用表格行内展开，不额外请求） |
| 对接任务二关系模型，五大场景可视化查询 | 「场景分析」页 → `/scenarios/s1` ~ `/scenarios/s5` |
| 界面简洁可用 | **三个页面**（一页对应一块赛题功能）、统一卡片布局、空态引导、筛选即查无需按钮 |
| 响应高效（<1 秒） | 固定 20 条/页、远程搜索不全量拉取、图谱限节点并自动隐藏重叠标签、图表关动画；界面实时显示耗时 |
| 前端 Vue / 后端 Python | Vue 3 + Vite / FastAPI |
| 评审方登录系统验证功能 | 需补：登录账号 + 图文操作说明（**待办**） |

**待办（合并前必须完成）：**

- [ ] 增加简单的登录/鉴权（评审方需要账号登录，赛题明确要求提供）
- [ ] 「图文操作说明」文档
- [ ] 接入真实数据后，把 `EDM_DATA_BACKEND` 切到 `real`
- [ ] 生产构建验证：`npm run build` 后单进程跑通全流程
- [ ] 用真实数据实测查询响应时间（当前演示规模 24 条，不代表真实规模）
