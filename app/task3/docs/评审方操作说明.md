## 四、上传与恢复（要点）

- 上传支持 4 条路线：含 `items_task1.csv` 的 zip；原始 HTML（含同名 `_file.zip`）；官方三表 xlsx；无 HTML 的单篇附件包。
- 当前库非空时会询问入库方式：**覆盖并上传**（替换）、**保留原数据并解析**（追加）、**X/Esc**（取消，不改动）。
- 上传后进度区显示「已完成」与「单篇 XX ms」，统计自动刷新，无需手动刷新。
- 需要回到交付基线时，点「恢复默认数据」→ 确认；会重建平台库（图库为 Neo4j 时一并重建），本机约 1–2 秒。
- 场景为空多因数据缺投标关系：只传官方三表或单篇附件包时，S2/S3 为空属正常，不是查询失败。

## 五、模型 Key 与合规

- Key **只从页面「模型配置」读取**（`EDM_KEY_SOURCE=ui`），不读环境变量/`.env`；页面只显示末 4 位掩码。
- 未配置 Key 时上传解析回退规则层；配置后路线②/④使用文本模型，路线①/③为结构化直接入库、不调用模型。
- 视觉模型分组可保存，但当前上传管线未启用视觉通道，扫描件/图片仍按规则层处理。
- 调用日志 `app/out/llm_calls.jsonl` 只含模型 id、耗时、token 等元数据，不含 Key 与原文。

## 六、部署与排障

- 启动：`cd app && uv run python task3/backend/run.py --host 0.0.0.0 --port 8000`。
- 页面打不开：查端口/安全组；静态资源 404：Ctrl+F5 强刷或重新解压 `task3/backend/static/`。
- 上传超限：默认 2 GB 上传、8 GB 解压上限；3.4 GB 原始整包建议用 `platform/ingest.py` 脱机入库。
- Neo4j 未启动：启动日志会提示并自动回退 SQLite；需要图库时确认 bolt 与口令后重启。
- 中文乱码：Linux `LANG=C.UTF-8`，Windows `PYTHONUTF8=1`；Windows 长路径解压到短目录或运行 `app/scripts/repair_long_paths.py`。

完整内容以《操作文档》为准；页面文案与文档有细微差异时，以当前版本页面为准。
