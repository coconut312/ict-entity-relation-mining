## 四、已知局限（如实披露）

1. **准确性 gold 非独立人工标注**：`valset/gold` 由 DeepSeek LLM 起底后用于对照，**P 1.00 / R 0.99 / F1 0.99 / A 0.99** 属"与同族标注的一致性"，**不等于人工核验精度**；需独立盲标 15–20 篇才能把该结论变为可采信。
2. **模型 id 声明**：所用接口 `/v1/models` 返回 `deepseek-flash` / `deepseek-v4-pro` 两个 id（本项目实际使用前者）；其是否等同于 DeepSeek 官方公开目录名称，本包不作判断。全量 1038 篇的历史抽取发生在引入调用日志之前，故日志覆盖范围见 `model_manifest.json` 的说明。
3. **S1「产品供应商」口径差异**：Neo4j 版取品牌供货关系，SQLite 版另含声明函制造商，两者在评测样例上数值相同但语义不完全等同。
4. **嵌套压缩包**：已支持 rar/7z（bsdtar 递归解压）；加密包无法解开（实测 23 篇中 2 个）。
5. **演示材料**：PPT / 汇报视频 / 系统演示视频 / 全程录屏**不在本包内**，需另行录制提交。

### 补充答疑：问题一 / 问题二

**问题一（投标不得拆包）**：官方明确「投标不能拆分包或对包中部分货物投标，投标必须以包为单位进行」
指的是**以包需求为单位完整应标**，投标人不得只响应包内部分标的；分歧原因是内容登记不全或
地方/中央网站同步数据的格式差异。→ **落实**：我们的抽取**不拆分标段/包**，一个包内的标的一并保留；
`标段/合同包` 无分包证据时填「未分包」、UUID 不加后缀（见 Q1）。

**问题二（中标标的 vs 采购需求/预算）**：官方明确
- 附件中的**招标文件、需求文件 = 计划采购的内容清单及预算**；
- **中标明细、中标一览 = 实际中标的标的及价格**；
- **命题要求提取的是「实际中标的标的及对应信息」，不是预算采购的标的**；
- 「做减法」（预算减去中标以推断缺项）**不属于强逻辑关系，不建议作为标注依据**（费用中还可能有税金、服务费等未公示内容）；
- 建议：以**公示与明细附件中明确采购的标的及成交信息为主**（这是精度评估的参考），
  预算/需求内容可提取后**通过增加字段区分「需求」与「中标标的」并附备注**，作为技术先进性材料。

→ **落实**：
1. 本数据集的公告 `notice_type` 分布为 **中标 370 / 成交 82 / 结果 585 / 其他 1 —— 全部为结果类**，
   因此标的表 `类别` **一律记「中标」**（此前把 `结果` 误判为「需求」，已修正）；
2. 标的表**新增 `备注` 列**（Q5 允许的自定义字段）：中标行注明「来源：结果公示/中标明细」，
   若出现需求/预算来源则注明「来源：招标/需求文件（计划采购，不计入精度评估）」，实现两类标的可区分；
3. **不做"做减法"推断**：我们仅按《官方回答》做**行内**逻辑推定（单价=总价÷数量 等，已标 `derived=True`），
   不跨条目推断缺项，也不从预算反推中标清单。

### 补充答疑：框架协议/公示入围/协议折扣的处理

官方答复：「框架协议/公示入围/协议折扣等仅明确采购意向、未公示具体成交细节的数据
**不计入提取率、精确度评估标准**，仅用于**检测提取算法是否出现幻觉**；若想增加提取展示，
可按表述方式自行设定后作为**展示创新和技术先进性的其他材料**」。

→ **落实**：
1. 生成 `app/deliverables/official/排除评估清单.csv`（列：UUID / 项目名称 / 公告类型 / 定价方式 / 排除原因），
   识别规则：① `定价方式` 属率/折扣/下浮/框架/协议类（无固定成交总价）；② 正文含
   「框架协议/入围/协议供货/协议采购/定点采购/电子卖场」等关键词。评估方**按此清单排除**即可。
2. **幻觉检查**：对上述公告统计我们是否填出成交细节（中标金额/中标供应商），
   如无原文依据一律按 Q2 **置空**，不臆造成交信息。
3. 这类数据保留在库中用于**展示**（创新性与技术先进性材料），但**不进入精度评估口径**。
