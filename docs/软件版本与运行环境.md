## 1. 运行环境

| 项目 | 开发 / 验证环境（实测） | 部署建议 |
|---|---|---|
| 操作系统 | **Windows 11 家庭版**（10.0.26200） | **Ubuntu 24.04 LTS x86_64**（命令以 bash 为例；Windows 10/11 同样可跑） |
| CPU / 内存 | 本机开发机（未固定规格） | **2 核 / 4 GB**（赛方评测同规格；平台常驻约 250–400 MB，无需 GPU） |
| 磁盘 | — | **≥ 8 GB 可用**；若还要解压赛方原始数据集（3.4 GB 压缩 + 约 4 GB 解压）另需 8 GB |
| Python | **3.14.4**（`app/.venv`，MSC v.1944 64 bit） | **3.14**（`app/.python-version` = `3.14`，`requires-python >= 3.14`） |
| uv | **0.11.9** | 0.5+ 即可，推荐与实测同版本 |
| Node.js | **v24.13.1** | **仅重新构建前端时需要**；正常部署用包内 `task3/backend/static/`，**不需要 Node** |
| Neo4j | **5.25.1 Community**（`CALL dbms.components()` 实测） | 5.25.x Community（可选；不装则平台自动回退 SQLite 图库） |
| Java（Neo4j 依赖） | **JDK 21**（`C:\Program Files\Java\jdk-21`） | JDK 17 / 21 均可 |
| SQLite | **3.50.4**（Python 3.14 内置 `sqlite3`） | 随 Python 内置，无需单独安装 |
| LibreOffice | 仅用于把 DOCX 转 PDF（交付文档生成阶段） | 运行平台不需要 |

**Neo4j 内存**：本机 `conf/neo4j.conf` **未显式设置** heap / pagecache（相关行均为注释，使用默认动态策略；实测 Neo4j 进程工作集约 **252 MB**）。在 2C4G 机器上建议显式设 `server.memory.heap.max_size=1G`、`server.memory.pagecache.size=512M`，这只是部署建议，不是本机实测配置。

```bash
export NEO4J_URI=bolt://127.0.0.1:7687
```

## 5. 源码功能说明（模块 → 职责 → 关键入口）

### 5.1 `app/ict_parse/` —— 任务一解析与抽取核心

| 模块 | 职责 | 关键入口 |
|---|---|---|
| `pipeline.py` | 单篇公告端到端：HTML + 附件包 → IR → 规则 / LLM 抽取 → 落盘 | `process_one()` |
| `attach.py` | 递归解压（zip/rar/7z，最深 8 层）、幻数嗅探、超长路径压缩、PDF / DOCX / XLSX / 图片文本化 | `extract_bundle()`、`extract_text_for()`、`_sniff()`、`_fit_path()` |
| `extract.py` | 规则层：表头归一、金额 / 数量归一、跨文件补价、正文成交块、报价方式、垃圾表 / 占位值过滤 | `build()`、`items_from_table()`、`_items_from_announcement_text()`、`_pricing_mode()` |
| `llm_extract.py` | LLM 层：公告分块、上下文拼装、JSON 强约束、块级并发、失败回退 | `extract_with_llm_safe()`、`build_chunks()`、`_call_plan()` |
| `official_tables.py` | 官方三表（总表 / 标的表 / 投标人表）生成，CSV / XLSX / 平台下载共用 | `build_tables()`、`build_from_platform()`、`write_xlsx()`、`write_csvs()` |
| `backfill.py` | **归位式回填**：只补空值、不覆盖，逐条写侧车溯源 | `apply()`、`append_provenance()` |
| `noise.py` | 标的行噪音过滤（行业分类词 / 行标签 / 纯标点 / 全空行 / 过短名），唯一实现 | `filter_items()`、`classify()` |
| `bidders.py` | 投标人名单（参与人、通过审查、得分、未中标原因） | `roster_from_rec()`、`merge_rows()` |
| `__main__.py` | 任务一 CLI：按公告号批量解析 + 抽取 | `main()` |

## 6. 执行步骤（安装 → 建库 → 建图 → 起服务 → 验证 → 复现）

以下命令均在**解压后的 `app/` 目录**执行（Windows 用 `.\.venv\Scripts\python.exe` 替代 `uv run python` 亦可）。

### 6.1 安装

```bash
uv python install 3.14
uv sync
```

### 6.2 建库（必做）

```bash
uv run python platform/ingest.py --db out/platform/platform.db
```

预期：`pages=1038`、`t1_item=6244`；服务库写入 `out/platform/platform.db`。

### 6.3 建图（可选，需 Neo4j）

```bash
export NEO4J_URI=bolt://127.0.0.1:7687
export NEO4J_USER=neo4j
export NEO4J_PASSWORD=<你的口令>
uv run python scripts/build_neo4j_graph.py --load --wipe --export
```

预期：装载 5,645 节点 + 14,157 关系，导出 `deliverables/neo4j/*.csv`（9 个，合计 19,802 行）。

### 6.4 起服务

```bash
uv run python task3/backend/run.py --host 0.0.0.0 --port 8000
```

浏览器打开 `http://<主机>:8000/`，账号 **reviewer / ict2026**；接口文档 `/api/docs`。

### 6.5 验证

```bash
uv run python task3/backend/smoke_test.py
# 预期：通过 58 项，失败 0 项；退出码 0

uv run python scripts/assert_official_consistency.py --dir deliverables/official
# 预期：A–E 全部断言通过，退出码 0

uv run python scripts/verify_neo4j.py --no-load \
  --uri bolt://127.0.0.1:7687 --user neo4j --password <口令>
# 预期：可比项 11 项，一致 11 项，不一致 0 项；退出码 0
```

### 6.6 复现交付物

```bash
# 任务一交付表（需 out/full/<id>/items_llm.json；本包 --with-raw-json 已含逐篇 JSON）
uv run python scripts/export_task1_tables.py

# 官方三表（只需 out/task2/graph.db + deliverables/items_task1.csv，本包内均有）
uv run python scripts/export_official_format.py

# 任务二 14 张关系 / 画像表（由任务一交付表重建）
uv run python scripts/build_task2_graph.py

# 重新打交付包
uv run python scripts/pack_delivery.py --with-raw-json
```

### 6.7 重新生成技术文档（可选）

```bash
uv run python scripts/md_to_docx.py ../docs/system-design-document.md deliverables/系统设计文档.docx
uv run python scripts/md_to_docx.py ../docs/process-document.md deliverables/过程性文档.docx
# 再用 LibreOffice 将 DOCX 转为 PDF（命令见《提交说明与运行指南》）
```

## 8. 已知限制（与版本 / 环境相关）

1. **Neo4j 内存未显式配置**：本机使用默认动态策略；生产 2C4G 建议按 §1 设置 heap / pagecache。
2. **Node 仅构建期需要**：包内 `task3/backend/static/` 已是构建产物，评审部署无需 Node。
3. **LLM API 不在包内**：平台默认不发起 LLM 调用；上传原始数据集且配置了 key 时才会调用（`openai 3.19.2`）。
4. **Python 3.14 为硬要求**：`pyproject.toml` 的 `requires-python >= 3.14`；低版本无法 `uv sync`。
